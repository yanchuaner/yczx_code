# 安全设计

## 预览版原则

模型输出是不可信输入。即使预览版只有读操作，也必须防止越界读取、敏感信息泄漏和资源耗尽。所有代码库工具都先经过同一套权限策略，不能各自临时判断。

## 工作目录

启动会话时记录经过解析的工作目录 `workspace_root`。工具收到路径后应：

1. 将相对路径基于 `workspace_root` 解析；
2. 规范化并解析符号链接；
3. 确认最终路径仍位于 `workspace_root` 内；
4. 再检查敏感路径和文件类型；
5. 最后执行读取。

绝对路径不是天然安全的。`../`、符号链接和大小写差异都不能绕过工作目录检查。

## 默认拒绝内容

首版至少拒绝：

- `.env` 和 `.env.*`；
- 常见私钥、证书和凭据文件；
- `.git/` 内部对象；
- `.venv/`、`node_modules/` 和构建缓存；
- 二进制文件、数据库和超出大小限制的文件。

忽略规则和安全拒绝规则含义不同：前者减少无关内容，后者即使用户或模型主动指定也不能读取。安全拒绝应返回明确但不泄露内容的错误。

## 资源限制

每轮请求需要明确限制：

- 最大 Agent 步数；
- 单个文件读取字节数和行数；
- 目录条目数和搜索结果数；
- 工具结果进入上下文的长度；
- 模型超时和重试次数。

达到限制时返回截断标记和继续读取所需的位置，不能静默丢失内容，也不能无限自动重试。

## 日志与展示

默认只展示工具名称、经过裁剪的参数和结果摘要。错误信息不能包含 API Key、Authorization 头、完整环境变量或未裁剪的文件内容。

预览版不持久化完整对话和工具结果。以后增加日志时，先定义保留期限、脱敏规则和用户清理方式。

## 后续高风险能力

文件写入和 Shell 不应只增加一个工具函数。进入该阶段前必须分别完成：权限级别、操作预览、用户确认、审计记录、超时、输出限制、失败恢复和端到端测试。任意一项缺失时，能力保持关闭。

## 必测场景

- `../` 逃逸工作目录；
- 指向工作目录外的符号链接；
- 直接或间接读取 `.env`；
- 大文件、二进制文件和超长单行；
- 搜索结果过多；
- 模型反复调用同一工具；
- 工具参数类型错误和不存在的工具。
